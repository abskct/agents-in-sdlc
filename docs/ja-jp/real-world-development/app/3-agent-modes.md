プロジェクトに小さな機能を追加しました。より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot app は組織の既存の作業方法に合わせ、正しいものを正しい方法で作成できるように設計されています。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスに沿って作業します。issue から新機能を作成し、コードが有効で、機能が期待どおりに動作することを確認し、最後にプロジェクトにマージします。

> [!NOTE]
> 機能の作業を続ける間、同じセッションを使います。通常は作業対象のファイルの種類ごとに異なるセッションや PR を使いますが、ここでは主な概念に集中するため、手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から新しいエージェント セッションを開始します。
- **Plan** モードで要件を定義します。
- **Autopilot** モードで新機能を実装します。
- コードをレビューします。
- ブラウザーキャンバスで機能を手動検証します。

機能の作業を続ける間に、リポジトリの命令を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、利用者はカテゴリとパブリッシャーでゲームを絞り込む必要があります。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、実装前に合意が必要な詳細があります。Plan モードでその内容を決め、Autopilot に範囲を明確に定めた実装を任せます。

## 背景

AI コーディング エージェントを開発に取り入れても、基本は変わりません。むしろ、さらに重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業の詳細を記した issue から始めます。
2. 実装する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行し、コードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードがレビューされ、継続的インテグレーションのプロセスが成功したら、マージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、ほとんどは上記の流れに沿っています。

この標準的な方法を守ることで、AI が生成したコードが要件を満たし、手作業で作成したコードと同じレビュー プロセスを通るようにできます。

## セッション モード

**セッション モード**は、エージェントにどの程度の自律性を与えるかを制御します。プロンプト フィールドの下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。実行前に計画をレビューして承認します。
- **Autopilot**: エージェントが完全に自律して作業し、入力を待たずにコードを作成してテストを実行し、反復します。

まず Plan モードで開始し、計画をレビューしてから、Autopilot で実装します。

## issue からセッションを開始する

開始する前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** の下にある Tailspin Toys リポジトリ フォルダーを選択し、リポジトリの上部のナビゲーションで **Issues** を選択します。**Allow users to filter games by category and publisher** を開きます。これはテンプレートにある既存の issue です。新たに作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

    ![GitHub Copilot app の issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. issue がセッションに添付されていることを確認し、モード セレクターから **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行するよう依頼します。ターミナルでは動作するのにセッションでは動作しない場合は、アプリの PATH またはバージョン管理ツールの設定を確認してから、アプリを完全に終了して再起動します。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで、npm を再インストールしないでください。

## フィルター機能を計画する

計画を立てると、Copilot がコードを書く前にアプローチをレビューできます。issue から始めたため、Copilot はすでに機能のリクエストをコンテキストとして把握しています。次を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、issue の受け入れ条件と計画を比較します。カテゴリとパブリッシャーによる絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが含まれていることを確認してください。複数のカテゴリをどう組み合わせるか、一致するゲームがない場合にどうなるかなど、明確でない動作について話し合います。

計画には、プロジェクトの既存ツールを使った lint、単体テスト、E2E テスト、型チェックを含めます。計画の範囲は、フィルター機能の実装とテストに絞ります。品質ワークフローが完了してから PR を作成します。承認する前に計画の修正を依頼し、後の検証のために issue の URL と合意した追加事項を控えておきます。

## Autopilot を明示的に承認する

計画に問題がなければ、**Approve and implement this plan**、または使用中のバージョンで同等のオプションを選択します。承認によってモードが自動で変わるとは限らないため、実際のモードを確認してください。モード表示が **Autopilot** になっていることを確かめます。

Copilot が実装を始めます。作成した計画に沿ってコードを生成し、テストも実行しながら、作業を反復します。

> [!NOTE]
> 承認するとすぐに実装が始まることがあるため、先に計画をレビューしてください。依存関係が不足している、またはポートが競合していると Copilot が報告した場合は、チェック完了と判断する前にセットアップの問題を解決します。自分が起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同じようにマージ前にレビューします。コードをレビューし、サイトを実行して問題がないか確認しましょう。

1. **Changes** を開き、フィルター機能の実装とテストを確認します。
2. 複数カテゴリとパブリッシャーの組み合わせも含め、結果を issue と承認した追加事項に照らし合わせます。変更が既存のリポジトリ命令に従っていることを確認します。
3. lint、単体テスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、影響するチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカル サーバーを再利用できます。以前のレッスンではなく、この worktree のサーバーをテストしていることを確認してください。

## 新機能を確認する

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、ブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトを使い、アプリを起動してブラウザーキャンバスでページを開くよう Copilot に依頼します。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザー ウィンドウが開きます。
3. カテゴリを選択し、結果が選択したカテゴリに一致することを確認します。フィルターを解除してからパブリッシャーを選択し、結果が選択したパブリッシャーに一致することを確認します。
4. カテゴリとパブリッシャーのフィルターを組み合わせ、結果を issue と承認した計画に照らし合わせます。複数カテゴリがサポートされる場合は、合意した組み合わせ方法も確認します。
5. 該当するゲームがない組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットし、すべてのゲームが再び表示されることを確認します。
6. 確認が終わったら、次のプロンプトを使い、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンでも同じセッションを使う

フィルター機能の PR は、まだ作成またはマージしないでください。レッスン 4 から 8 まで、同じセッション、worktree、ブランチを使います。次はカスタム命令をフィルター機能のコードに適用し、スキルと QA の改善を追加してから、レッスン 8 で PR を作成してマージします。開発サーバーを停止した後、セッションをそのままにしてもかまいません。次のレッスンで同じセッションに戻ります。

- **Autopilot** モードで新機能を実装しました。
