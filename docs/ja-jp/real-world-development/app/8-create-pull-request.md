フィルター機能の実装、命令の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。まとめてレビューして、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスを任せます。

> [!NOTE]
> 通常は、機能、命令の更新、スキルの更新、QA エージェントを複数の PR に分けます。このワークショップでは手順を簡潔にするため、フィルター機能と品質ワークフロー全体を 1 つのセッションとブランチで進め、1 つの PR にまとめています。

このレッスンでは、次のことを行います。

- Agent Merge とは何か、マージ ライフサイクルを自動化する方法を学びます。
- 機能の PR 全体と検証の根拠を確認します。
- レビュー後に限り Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフロー全体を通じて、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys は、マージを許可する権限を開発者が保持したまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge の概要

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み込み、CI チェックの失敗やレビュー コメントへの対応、必要な場合のリベースなど、マージを妨げている問題を解決します。その後、GitHub が許可するとマージします。バックグラウンドで実行され、アプリを再起動しても継続し、プルリクエストがマージされると自動的に停止します。

ここまでは、自分で **Merge pull request** を選択していました。Agent Merge にその役割を任せることができますが、コードの編集やマージには引き続き明示的な許可が必要です。マージを許可する前に、許可する操作と作業内容をレビューしてください。

## Agent Merge で PR を管理する

すべてのコードを作成してレビューできたので、Agent Merge に PR のプロセスを任せましょう。

1. エージェント ピッカーから **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択して処理を開始します。ドロップダウンのオプションを選ぶだけでは開始されません。

Agent Merge の処理が始まります。次のことを行います。

- タイトルと説明を付けてプルリクエストを作成します。
- issue からセッションを開始した場合は、説明の本文で関連する issue を参照します。
- ターゲット ブランチにリベースするか、マージ競合に対処します。
- CI を監視し、すべてのチェックが成功することを確認します。
- 他の開発者や Copilot コード レビューからのフィードバックを確認し、コメントを解決するために変更を加えます。
- 必要に応じて、すべての処理が成功した後に PR を自動的にマージします。

すべてのチェックが成功したら、Agent Merge が PR もマージするように設定しましょう。

5. マージを許可する前に、PR の差分と検証の根拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** にチェックが付いていることを確認します。
8. 次のようにエージェントに明示して、マージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進捗を確認し、報告されたブロッカーに対応します。次に進む前に、PR の状態が **Merged** であることを確認します。マージの許可を有効にしたことやエージェントが実行中であることだけでは、マージ完了の確認になりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行前に、それらのブロッカーを解決してください。
